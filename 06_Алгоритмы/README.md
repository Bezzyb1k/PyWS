# Пузырьковая сортировка (Bubble Sort)

Пузырьковая сортировка - это простеший алгоритм сортировки, который сравнивает соседние элементы и меняет их местами, если они стоят в неправильном порядке

---

## Как это работает

1. Проходим по списку от начала до конца
2. Сравниваем каждый элемент с его соседом справа
3. Если левый больше правого - меняем их местами
4. Повторяем проходы, пока список не станет отсортированным

С каждым проходом самый большой элемент "всплывает" в конец списка

---

## Когда использовать

- Для обучения
- Для маленьких списков (до 100 элементов)
- Когда важда простота кода, а не скорость

---

## Когда не использовать

- Для больших списков - слишком медленно
- Когда важна производительность

---

# Быстрая сортировка (Quick Sort)

Быстрая сортировка — это один из самых эффективных алгоритмов сортировки.
Он работает по принципу "разделяй и властвуй": выбирает опорный элемент
(pivot), разделяет список на две части (меньше и больше pivot) и
рекурсивно сортирует каждую часть

---

## Как это работает

1. Выбираем опорный элемент (pivot)
2. Разделяем список на три части:
   - элементы меньше pivot
   - элементы равные pivot
   - элементы больше pivot
3. Рекурсивно сортируем левую и правую части
4. Соединяем результаты

---

## Аналогия

Представь, что ты разбираешь колоду карт. Ты берёшь одну карту (pivot)
и раскладываешь остальные на две стопки: меньше и больше. Потом делаешь
то же самое с каждой стопкой, пока все карты не будут отсортированы

---

## Два подхода

### 1. С созданием новых списков (проще для понимания)
```
def quick_sort(arr):
    if len(arr) <= 1:
        return arr
    pivot = arr[len(arr) // 2]
    left = [x for x in arr if x < pivot]
    middle = [x for x in arr if x == pivot]
    right = [x for x in arr if x > pivot]
    return quick_sort(left) + middle + quick_sort(right)
```
Плюс: код короткий и понятный
Минус: создаёт много новых списков, тратит память

### 2. In-place (эффективнее, но сложнее)
```
def quick_sort_in_place(arr, low = 0, high = None):
    if high is None:
        high = len(arr) - 1
    if low < high:
        pivot_index = partition(arr, low, high)
        quick_sort_in_place(arr, low, pivot_index - 1)
        quick_sort_in_place(arr, pivot_index + 1, high)
```
Плюс: не тратит память на новые списки.
Минус: сложнее для понимания.

---

## Когда использовать

- Для больших списков (1000+ элементов)
- Когда важна скорость
- Когда память ограничена (in-place версия)

---

## Когда НЕ использовать

- Когда список уже отсортирован
- Когда важна стабильность сортировки (Quick Sort нестабилен)

---

# Бинарный поиск (Binary Search)

Бинарный поиск — это алгоритм поиска элемента в отсортированном списке
Он работает по принципу "разделяй и властвуй": на каждом шаге отбрасывает
половину списка, в которой искомого элемента точно нет

---

## Важное условие

Бинарный поиск работает ТОЛЬКО на отсортированном списке
Если список не отсортирован — сначала нужно его отсортировать

---

## Как это работает

1. Находим середину списка
2. Сравниваем искомый элемент с элементом в середине
3. Если совпало — возвращаем индекс
4. Если искомый больше — ищем в правой половине
5. Если меньше — ищем в левой половине
6. Повторяем, пока не найдём или пока не останется пустой диапазон


---

## Сравнение с линейным поиском

| Линейный поиск | Бинарный поиск |
|----------------|----------------|
| O(n) | O(log n) |
| Работает на любом списке | Только на отсортированном |
| Перебирает все элементы | Делит список пополам |
| Медленно на больших данных | Быстро на больших данных |

Пример: в списке из 1000 элементов линейный поиск может сделать
1000 шагов, а бинарный — всего 10

---

## Когда использовать

- Когда список отсортирован
- Когда нужно часто искать элементы в одном и том же списке
- Когда список большой (1000+ элементов)

---

## Когда НЕ использовать

- Когда список не отсортирован (сначала сортируй)
- Когда список маленький (линейный поиск проще)
- Когда элементы часто меняются (сортировка занимает время)

---


# Big O нотация

Big O — это способ оценить, как быстро растёт время выполнения алгоритма
при увеличении входных данных. Это не секунды, а математическая оценка

---

## Зачем это нужно

- Понять, какой алгоритм быстрее
- Предсказать, как поведёт себя программа на больших данных
- Выбрать правильный инструмент для задачи

---

## Основные виды сложности

| Нотация | Название | Пример | Что значит |
|---------|----------|--------|------------|
| O(1) | Константная | Доступ по индексу | Время не зависит от размера |
| O(log n) | Логарифмическая | Бинарный поиск | Каждый шаг делит данные пополам |
| O(n) | Линейная | Поиск максимума | Время растёт пропорционально |
| O(n log n) | Линеарифмическая | Быстрая сортировка | Оптимально для сортировок |
| O(n²) | Квадратичная | Пузырьковая сортировка | Время растёт как квадрат |
| O(2^n) | Экспоненциальная | Перебор подмножеств | Очень быстро становится неприменимой |

---

## Примеры в коде

### O(1) — Константная
```
def get_first(arr):
    return arr[0]
```
Не важно, 10 элементов в списке или 10 миллионов — время одно и то же

---

### O(n) — Линейная
```
def find_max(arr):
    max_val = arr[0]
    for num in arr:
        if num > max_val:
            max_val = num
    return max_val
```
Проходим по всем элементам. Чем больше список, тем дольше

---

### O(log n) — Логарифмическая
```
def binary_search(arr, target):
    left, right = 0, len(arr) - 1
    while left <= right:
        mid = (left + right) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1
```
Каждый шаг отбрасывает половину. 1000 элементов — 10 шагов

---

### O(n²) — Квадратичная
```
def has_duplicates(arr):
    for i in range(len(arr)):
        for j in range(i + 1, len(arr)):
            if arr[i] == arr[j]:
                return True
    return False
```
Двойной цикл. 1000 элементов — 500 000 проверок

---

### O(n log n) — Линеарифмическая
```
def quick_sort(arr):
    if len(arr) <= 1:
        return arr
    pivot = arr[len(arr) // 2]
    left = [x for x in arr if x < pivot]
    middle = [x for x in arr if x == pivot]
    right = [x for x in arr if x > pivot]
    return quick_sort(left) + middle + quick_sort(right)
```
Лучший случай для сортировки. Быстрее, чем O(n²)

---

## Как понять, что важно

| Элементов | O(n) | O(n²) | O(log n) |
|-----------|------|-------|----------|
| 10 | 10 | 100 | 3 |
| 100 | 100 | 10 000 | 7 |
| 1000 | 1000 | 1 000 000 | 10 |
| 10000 | 10000 | 100 000 000 | 14 |

Разница становится критичной на больших данных

---

## Как оценить сложность своего кода

1. Посмотри на циклы. Один цикл — O(n) Два вложенных — O(n²)
2. Посмотри на рекурсию. Если каждый шаг делит данные пополам — O(log n)
3. Посмотри на встроенные функции. `list.append()` — O(1), `list.pop(0)` — O(n)

---

- Оптимизация кода 
- Выбор алгоритма (сортировка, поиск, обход)
- Работа с большими данными (когда важна каждая миллисекунда)
