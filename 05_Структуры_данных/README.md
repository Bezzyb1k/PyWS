# Стек

Стек - это структура данных, работающая по принципу LIFO (Last In, First Out)
Последний добавленный элемент покидает стек первым

---

## Важное уточнение

Мы создаем стек с нуля через класс "Stack"
Это сделано для понимания внутреннего устройста
В Python нет отдельного встроенного типа "Стек", но список list уже поддерживает похожие операции: `append()` для добавления в конец и `pop()` для удаления с конца

Наша реализация нужна, чтобы
- скрыть внутренние детали (инкапсуляция)
- отставить только нужные методы
- чётко показать логику работы стека

---

## Аналогия

Стек похож на стопку тарелок
Ты кладешь новую тарелку сверху и берешь тоже сверху
Середина или низ стопки недопступы, пока не убраны верхние тарелки

---

## Методы

| Метод | Назначение |
| ----- | ---------- |
| push(item) | Добавляет элемент на вершину стека |
| pop() | Убирает и возвращает верхний элемент |
| peek() | Показывает верхний элемент без удаления |
| is_empty() | Проверяет, пуст ли стек |
| size() | Возвращает количество элементов |

---

## Где применяется

- Отмена действий - каждое действие пользователя сохраняется в стек. Когда пользователь нажимает "оменить", последнее действие извлекается и откатывается
- История браузера - каждая новая страница, которую ты открываешь, добавляется в стек. Кнопка "назад" берет последнюю страницу и удаляет её
- Вызовы функций - когда программа вызывает функцию, Python сохраняет текущее сосотяние в стеке. Когда функция завершается - состояние овсстанавливается
- Проверка парности скобок в коде - компиляторы и редакторы кода проверяют, правильно ли рассталвены скобки в выражении
- Восстановление системы после сбоя - некоторые системы сохраняют все действия в стеке. При сбое можно "перемотать" систему назад, повторяя действия из стека (пример NixOS)

---

## Когда стек не подходит

- Если нужен доступ к элементам по индексу
- Если нужен порядок FIFO (первйы пришел - первый ушел) - для этого есть очередь


# Очередь

Очередь - это структура данных, работающая по принципу FIFO (First In, First Out)
Первый добавленный элемент покидает очередь первым

---

## Аналогия

Очередь похожа на очередь в магазине. Первый, кто встал, первым и уходит
Ты не можешь подойти к кассе из середины очереди - только с начала

---

## Методы

| Метод | Назначение |
| ----- | ---------- |
| enqueque(item) | Добавляет элемент в конец очереди |
| dequeue() | Убирает и возвращает первый элемент |
| peek() | Показывает первый элемент без удаления |
| is_empty() | Проверяет, пуста ли очередь |
| size() | Возвращает количество элементов |

---

## Где применяется

### 1. Обработк азадач в порядке поступления

**Что происходит:** Задачи приходят в систему и обрабатываются в том порядке, в котором поступили

**Почему очередь:** Если задачи обрабатывать в порядке поступления, никто не останется без внимания. Очередь гарантирует честный порядок

### 2. Буферизация данных (потоковая передача)

**Что происходит:** Данные приходят быстрее, чем их можно обработать. Очередь временно хранит их, пока обработчик не освободится

**Почему очередь:** Данные должны обрабатываться в том порядке, в котором пришли. Если использовать стек, порядок нарушится

---

### 3. Обход графа в ширину (BFS)

**Что происходит:** BFS обходит граф слоями: сначала все соседи стартовой вершины, потом соседи соседей и так далее

**Почему очередь:** BFS должен обрабатывать вершины в порядке их обнаружения. Очередь гарантирует, что вершины одного уровня обрабатываются раньше, чем вершины следующего

---

### 4. Планирование задач

**Что происходит:** Операционная система распределяет время процессора между задачами

**Почему очередь:** Задачи должны получать время в порядке поступления. Очередь гарантирует, что ни одна задача не будет забыта

---

### 5. Асинхронная обработка (очереди сообщений)

**Что происходит:** Сообщения от разных источников собираются в очередь и обрабатываются по одному

**Почему очередь:** Сообщения должны обрабатываться в порядке поступления. Очередь гарантирует, что ни одно сообщение не потеряется

---

## Отличие от стека

| Стек | Очередь |
| ---- | ------- |
| LIFO (Последний пришел - Первый ушел) | FIFO (Первый пришел - Первый ушел) |
| Добавление и удаление с одного конца | Добавление с одного конца, удаление с другого |

---

## Когда очередь не подходит

- если нужен доступ к элементам по индексу
- если нужен порядок LIFO

---


# Связный список

Связный список - этор структура данных, где каждый элемент (узел) хранит значение и ссылку на следующий элемент. В отличие от обычного списка, элементы не лежат в памяти подряд - они связаны ссылками

---

## Аналогия

Связный список похож на цепочку людей, держащихся за руки
Каждый человек знает только того, кто стоит перед ним, и того, кто за ним
Чтобы найти кого-то в цепочке, нужно идти от начала и спрашивать каждого

---

## Структура

Узел (Node):
- value - значение
- next - ссылка на следующий узел

Список (LinkedList):
- head - первый узел
- size - количество элементов

---

## Методы

| Метод | Назначение |
| ----- | ---------- |
| append(value) | Добавляет элемент в конец списка |
| prepend(value) | Добавляет элемент в начало списка |
| remove(value) | Удаляет первое вхождение элемента |
| find(value) | Проверяет, есть ли значение в списке |
| is_empty() | Проверяет, пуст ли список |
| size() | Возвращает количество элементов |

---

## Где применяется

### 1. Динамические структуры данных

**Что происходит:** Связный список может расти и уменьшаться во время работы программы. Не нужно заранее знать размер

**Почему связный список:** В отличие от массива, не нужно пересоздавать всю структуру при добавлении элемента. Просто меняются ссылки

### 2. Реализация стеков и очередей

**Что происходит:** Стек и очередь можно реализовать на основе связного списка. Это дает преимущество в скорости добавления и удаления

**Почему связный список:** В обычном списке удаление из начала требует сдвига всех элементов. В связном списке - просто меняется ссылка

### 3. Хранение больших объёмов данных

**Что происходит:** Когда данные не помещаются в один блок памяти, связный список позволяет разбросать их по разным блоками и связать ссылками

**Почему связный список:** Не нужен непрерывный участок памяти. Каждый узел может лежать где угодно, главное - ссылка

### 4. Редакторы текста (Буфер обмена)

**Что происходит:** В редакторах текста часто используется связный список для хранения символов или строк

**Почему связный список:** Вставка и удаление символов в середине текста требует изменение только ссылок, а не сдвига всего текста

### 5. Графы и деревья

**Что происходит:** Связные списки используются для представления списков смежности в графах

**Почему связный список:** Каждая вершина графа хранит список своих соседей. Связный список позволяет эффективно добавлять и удалять соседей

---

## Отличие от обычного списка (list)

| Список (list) | Связный список |
| ------------- | -------------- |
| Элементы лежат подряд в памяти | Элементы разбросаны по памяти |
| Доступ по индексу за O(1) | Доступ по индексу за O(n) |
| Вставка в середину - сдвиг всех элементов | Вствка в середину - изменеине ссылок |
| Удаление изначала - сдвиг всех элементов | Удаление из начала - изменение ссылки |
| Занимает больше памяти (резерв) | Занимает ровно столько, сколько нужно |

---

## Когда связный список не подходит

- если нужен частный доступ к элементам по индексу
- если нужно часто искать элементы (поиск всегда с начала)
- если важна экономия памяти (каждый ущел хранит ссылку)

# Хеш-таблица

Хеш-таблица - это структура данных, которая хранит пары ключ → значение
и позволяет находить значение по ключу почти мгновенно

---

## Важное уточнение

Мы создаём хеш-таблицу с нуля через класс `HashTable`. Это сделано для
понимания внутреннего устройства. В Python уже есть встроенный словарь
(`dict`), который работает по такому же принципу, но реализован на C

Наша реализация нужна, чтобы:
- понять, как работает хеш-функция
- увидеть, как решаются коллизии
- научиться управлять данными на низком уровне

---

## Аналогия

Хеш-таблица похожа на шкаф с ящиками. У каждого ящика есть номер.
Когда ты кладёшь вещь, ты вычисляешь номер ящика по названию вещи
(хеш-функция) и кладёшь туда. Когда хочешь достать — снова вычисляешь
номер и открываешь нужный ящик

---

## Как это работает

1. Есть массив "корзин" (buckets) фиксированного размера
2. Хеш-функция превращает ключ в число (индекс корзины)
3. Пара ключ → значение кладётся в корзину по этому индексу
4. Если два ключа попали в одну корзину — это коллизия
5. Коллизии решаются методом цепочек: в каждой корзине лежит список пар

---

## Методы

| Метод          | Назначение                                      |
|----------------|-------------------------------------------------|
| set(key, value)| Добавляет или обновляет пару                    |
| get(key)       | Возвращает значение по ключу (или None)         |
| remove(key)    | Удаляет пару по ключу                           |
| contains(key)  | Проверяет, есть ли ключ                         |
| keys()         | Возвращает все ключи                            |
| values()       | Возвращает все значения                         |
| items()        | Возвращает все пары ключ → значение             |
| size_of()      | Возвращает количество элементов                 |

---

## Где применяется

### 1. Словари и базы данных

**Что происходит:** Хеш-таблицы используются для быстрого поиска данных
по ключу

**Почему хеш-таблица:** Поиск занимает почти мгновенное время, независимо
от количества элементов


### 2. Кеширование

**Что происходит:** Результаты вычислений сохраняются в хеш-таблице,
чтобы не вычислять их повторно

**Почему хеш-таблица:** Быстрый доступ к сохранённым результатам


### 3. Подсчёт частоты

**Что происходит:** Подсчитывается, сколько раз встречается каждый элемент

**Почему хеш-таблица:** Ключ — элемент, значение — счётчик


### 4. Индексы в базах данных

**Что происходит:** Базы данных используют хеш-таблицы для ускорения
поиска по индексированным полям

**Почему хеш-таблица:** Поиск по индексу быстрее, чем полный перебор


### 5. Множества (set)

**Что происходит:** Множества в Python реализованы на основе хеш-таблиц

**Почему хеш-таблица:** Проверка наличия элемента занимает почти мгновенно

---

## Отличие от обычного списка

| Список (list) | Хеш-таблица |
|---------------|-------------|
| Поиск за O(n) | Поиск за O(1) |
| Доступ по индексу | Доступ по ключу |
| Порядок сохраняется | Порядок не гарантируется |
| Можно хранить дубликаты | Ключи уникальны |

---

## Когда хеш-таблица не подходит

- если нужен доступ к элементам по индексу
- если нужен порядок элементов
- если ключи должны быть изменяемыми (списки нельзя использовать как ключи)
